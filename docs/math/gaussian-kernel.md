# gaussian_kernel：コード⇔数式対応

[← 数式⇔コード対応資料トップへ](README.md)　｜　関連：[2-2. カーネルプリセット](../features/2-convolution/2-2-kernel-presets.md)

## コード

```python
def gaussian_kernel(size: int = 3, sigma: float = 1.0) -> np.ndarray:
    half = size // 2
    coords = np.arange(-half, half + 1, dtype=np.float64)
    x, y = np.meshgrid(coords, coords)
    kernel = np.exp(-(x**2 + y**2) / (2 * sigma**2))
    return kernel / kernel.sum()
```

## 数式

2次元ガウス分布の確率密度関数は以下の通り。

```
G(x, y) = (1 / (2π σ²)) * exp(-(x² + y²) / (2σ²))
```

このコードでは定数係数`1/(2πσ²)`を省略し（後で全体を総和で正規化するため不要になる）、残りの部分をカーネルの各位置でサンプリングしてから正規化する。

```
K(i, j) = exp(-(i² + j²) / (2σ²)) / Σ exp(-(i'² + j'²) / (2σ²))
                                    （分母は全ての i', j' についての総和）
```

## コードと数式の対応

### `half = size // 2`

数式上は`k = (n-1)/2`（`n`は奇数のカーネルサイズ）に相当し、**カーネル中心から端までの最大オフセット**を表す。

ガウス関数`G(x,y) = exp(-(x²+y²)/2σ²)`は「原点（中心）からの距離」で値が決まる関数で、中心`(0,0)`が最大値、離れるほど小さくなる。しかしNumPyの配列は`0, 1, 2, ..., size-1`という**先頭からの通し番号**でインデックスされる。この通し番号をそのままガウス関数に代入すると、本来`0`であるべき中心が`index=1`（3×3なら）にズレてしまい、正しい山型の形にならない。

`half`はこのズレを解消するための値。「配列のインデックス」と「数式上の中心からの距離」を対応づける橋渡し役になる。

### `coords = np.arange(-half, half + 1)`

`half`を使って、`-k, ..., 0, ..., k`という**中心からの相対的なオフセット**の配列を作る（数式の`i`や`j`が取りうる値そのもの）。`size=3`なら`[-1, 0, 1]`になる。

| 配列のインデックス | `coords`の値（中心からの距離） |
|---|---|
| 0（先頭） | `-1` |
| 1（中央） | `0`（＝ガウス関数の原点、ピーク） |
| 2（末尾） | `+1` |

これにより、配列の中央（`coords[1]`）が数式上の原点`0`に対応するようになり、ガウス関数の山の頂点が配列の中心と正しく一致する。

### `x, y = np.meshgrid(coords, coords)`

`coords`（1次元、長さ`n`）から、全ての`(i,j)`の組み合わせを表す2つの2次元配列`x, y`（ともに`n×n`）を作る。`x[a,b]`と`y[a,b]`のペアが、カーネル上の位置`(a,b)`に対応する`(i,j)`の値になる。数式でいう「`i`を`-k`から`k`まで、`j`を`-k`から`k`まで動かして全ての組み合わせを考える」という二重ループを、ループを書かずに配列操作として一括生成している。

### `np.exp(-(x**2 + y**2) / (2 * sigma**2))`

`exp(-(i²+j²)/(2σ²))`を、`x, y`で表現された全ての格子点`(i,j)`について同時に計算する（これが正規化前の`K(i,j)`）。`x**2 + y**2`は各格子点での`i²+j²`（原点からの距離の2乗）に対応し、NumPyの要素ごとの演算により、forループなしで`n×n`個の値が一度に求まる。

### `kernel.sum()`

数式の分母`Σ exp(-(i'²+j'²)/(2σ²))`（全要素の総和）に対応する。`kernel`配列の全要素を1つのスカラー値に合計する。

### `kernel / kernel.sum()`

正規化前の`kernel`を、その総和で割る。これが最終的な`K(i,j)`（戻り値）になる。「総和で割る」という操作により、どんな`size`・`sigma`の組み合わせでも、戻り値の全要素の合計が必ず`1`になることが保証される（[mean_kernel](mean-kernel.md)で重みの合計が`1/n²×n²=1`になるのと同じ、「明るさの総量を保存する」という目的）。

## 具体的な計算例（3×3, sigma=1.0, size=3）

`half=1`なので、添字`i,j`は`-1, 0, 1`を取る。各格子点で`exp(-(i²+j²)/2)`を計算する（正規化前の生の値）。

```
exp(-(1²+1²)/2) = exp(-1)   ≈ 0.367879   … 四隅 (|i|=1, |j|=1)
exp(-(1²+0²)/2) = exp(-0.5) ≈ 0.606531   … 上下左右 (|i|=1,j=0 または i=0,|j|=1)
exp(-(0²+0²)/2) = exp(0)    = 1.0        … 中心 (i=0, j=0)
```

正規化前の行列：

```
| 0.367879  0.606531  0.367879 |
| 0.606531  1.0       0.606531 |
| 0.367879  0.606531  0.367879 |
```

総和：`4×0.367879 + 4×0.606531 + 1×1.0 = 4.897640`

この総和で各要素を割ると、正規化後の最終的なカーネル（`gaussian_kernel(3, 1.0)`の実際の戻り値）になる。

```
| 0.075114  0.123841  0.075114 |
| 0.123841  0.204180  0.123841 |
| 0.075114  0.123841  0.075114 |
```

全要素を足すとちょうど`1`になる（正規化の目的通り）。中心が最大値（`0.204180`）で、外側に行くほど小さくなっている＝中心に近いピクセルほど強く、遠いピクセルほど弱く影響する、という「ぼかし」の重みになっている。
