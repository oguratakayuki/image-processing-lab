# 物差し（基準波）で信号を測るという見方（補足資料）

[← 6-1. 離散フーリエ変換（1次元）へ戻る](6-1-dft.md)

## 超ざっくり言うと

[(式1)](6-1-dft.md)の`exp(-2πikn/N)`は、信号の値とは無関係に`k`と`n`だけで先に決まる「物差し（基準波）」。DFTは、信号の各点をこの物差しに掛けて複素平面上のベクトルとして足し合わせ、「信号がこの物差しとどれだけ似ているか」を測る操作になっている。

## 📊 物差しが信号を測る様子（図解）

![物差し（基準波）が信号を測る様子（複素平面でのベクトル合成）](assets/6-1-dft-ruler-vector-sum.svg)

`N=8`の余弦波信号`x_n = cos(2πn/8)`を例に、周波数`k=1`（信号と一致する物差し）と`k=3`（一致しない物差し）それぞれで、8つの項`x_n・exp(-2πikn/N)`を複素平面上のベクトルとして矢印でつなげた図。

## 概念

[6-1本編](6-1-dft.md)の[(式1)](6-1-dft.md)`X_k = Σ x_n・exp(-2πikn/N)`をもう一度見ると、`exp(-2πikn/N)`の部分には、信号の値`x_n`が一切登場しない。この部分は、[複素平面の単位円](6-1-dft-complex-numbers.md)上を、`k`と`n`だけで決まる角度だけ回転させた点——いわば**「周波数`k`を測るための物差し」**を、先に`n=0`から`N-1`まで用意しているだけ。

DFTは、この物差しの各目盛り`exp(-2πikn/N)`に、信号の値`x_n`を掛けて（物差しをその分だけ伸び縮みさせて）、`N`個のベクトルとして複素平面上に並べ、それを全部足し合わせる。信号が物差しの周波数と**似ているほど、ベクトルは同じような向きを向いて足し合わさり、大きな合計**になる。似ていなければ、ベクトルはバラバラな方向を向き、**足し合わせると打ち消し合って小さく（0に近く）**なる。

これは「ベクトル同士を見比べて似ているか判定する」という専用のステップではなく、各ベクトルをただ足し続けた結果として自然に現れる現象であることに注意（コードの`total += signal[n] * np.exp(1j * angle)`は毎回の累積加算だけで、比較ロジックは一切含まれない）。

## 実数`x_n`はどうやってベクトルになるのか

信号データ`x_n`自体は、向きを持たないただの**実数（スカラー）**であり、それ単体ではベクトルではない。ベクトルになるのは、**複素数である物差し`exp(-2πikn/N)`に掛け算される瞬間**。

```
x_n                         … 実数（例: 0.7071）
exp(-2πikn/N)                … 複素数（複素平面上の1点＝ベクトル）
x_n・exp(-2πikn/N)            … 複素数（＝ベクトル）
```

実数を複素数に掛けるという演算は、「ベクトルの長さを`x_n`倍に伸び縮みさせる（`x_n`が負なら180度反転させる）」という操作そのものにあたる。つまり`x_n`は、物差し側がすでに用意しているベクトルの**長さ（と符号）を決めるだけの役割**であり、向きは物差し`exp(-2πikn/N)`の角度がそのまま使われる。

## 具体的な計算例

`N=8`の信号`x_n = cos(2πn/8)`（[6-1本編の数値例](6-1-dft.md)と同じ信号）で、`k=1`と`k=3`の2つの物差しを比較する。

**`k=1`（信号と一致する物差し）**：各項`x_n・exp(-2πi・1・n/8)`を計算すると

```
n=0: x_n=+1.0000, 物差し(角度   0度)=1.0000+0.0000j, 項=1.0000+0.0000j
n=1: x_n=+0.7071, 物差し(角度 -45度)=0.7071-0.7071j, 項=0.5000-0.5000j
n=2: x_n=+0.0000, 物差し(角度 -90度)=0.0000-1.0000j, 項=0.0000+0.0000j
n=3: x_n=-0.7071, 物差し(角度-135度)=-0.7071-0.7071j, 項=0.5000+0.5000j
n=4: x_n=-1.0000, 物差し(角度-180度)=-1.0000+0.0000j, 項=1.0000+0.0000j
n=5: x_n=-0.7071, 物差し(角度-225度)=-0.7071+0.7071j, 項=0.5000-0.5000j
n=6: x_n=-0.0000, 物差し(角度-270度)=0.0000+1.0000j, 項=0.0000+0.0000j
n=7: x_n=+0.7071, 物差し(角度-315度)=0.7071+0.7071j, 項=0.5000+0.5000j
合計 X_1 = 4+0j
```

上の図（k=1パネル）は、この8つの「項」を矢印として順につなげたもの。信号が物差しと一致しているため、ベクトルは全体として右方向（実軸のプラス方向）に積み上がっていき、最終的に`(4, 0)`に到達する。

**`k=3`（信号と一致しない物差し）**：同じ信号を、周波数3の物差しで測ると

```
n=0: x_n=+1.0000, 物差し(角度   0度)=+1.0000+0.0000j, 項=+1.0000+0.0000j
n=1: x_n=+0.7071, 物差し(角度-135度)=-0.7071-0.7071j, 項=-0.5000-0.5000j
n=2: x_n=+0.0000, 物差し(角度-270度)=-0.0000+1.0000j, 項=-0.0000+0.0000j
n=3: x_n=-0.7071, 物差し(角度-405度)=+0.7071-0.7071j, 項=-0.5000+0.5000j
n=4: x_n=-1.0000, 物差し(角度-540度)=-1.0000-0.0000j, 項=+1.0000+0.0000j
n=5: x_n=-0.7071, 物差し(角度-675度)=+0.7071+0.7071j, 項=-0.5000-0.5000j
n=6: x_n=-0.0000, 物差し(角度-810度)=+0.0000-1.0000j, 項=-0.0000+0.0000j
n=7: x_n=+0.7071, 物差し(角度-945度)=-0.7071+0.7071j, 項=-0.5000+0.5000j
合計 X_3 = 0+0j
```

図（k=3パネル）を見ると、8つのベクトルが三角形を描くように進み、最終的に出発点（原点）にぴったり戻ってくる。`n=4〜7`の4項は、信号の対称性により`n=0〜3`と全く同じベクトルの並びを繰り返すため、同じ三角形の経路をもう一周する形になる。向きがバラバラなベクトルを足し合わせた結果、打ち消し合って合計が`0`になる。

### なぜ厳密に0になるのか（偶然ではない理由）

「たまたま四捨五入して0に近い値になった」のではなく、**厳密に0**であることが計算上保証されている。実際に`term0`から`term3`までの4項だけを先に足すと、それだけでちょうど`0`になる（`n=4〜7`は同じ4項をもう一度足しているだけなので、合計はその2倍＝やはり`0`）。

```
term0+term1+term2+term3 = (1+0j) + (-0.5-0.5j) + (0+0j) + (-0.5+0.5j) = 0+0j
```

これは[オイラーの公式の補足資料](6-1-dft-euler-formula.md)で確認した`cos(θ) = (exp(iθ)+exp(-iθ))/2`という分解を使うと一般的に説明できる。信号`x_n = cos(2π・1・n/8)`を2つの複素指数の和に分解してから、周波数`k=3`の物差しを掛けると

```
x_n・exp(-2πi・3・n/8) = (1/2)・exp(-2πi・2・n/8) + (1/2)・exp(-2πi・4・n/8)
```

という2つの項に分かれる（指数の肩が`1-3=-2`と`-1-3=-4`になる）。それぞれを`n=0`から`7`まで足し合わせると、[複素指数関数の直交性](6-1-dft-euler-formula.md)（`Σ exp(i2πmn/N)`は`m`が`N`の倍数でない限り`0`になる、という性質）により、`m=-2`も`m=-4`も`8`の倍数ではないため、**どちらの和も厳密に0**になる。

```
Σ exp(-2πi・2・n/8) = 0   （実際に計算して確認済み）
Σ exp(-2πi・4・n/8) = 0   （同上）
```

つまり`k=3`で合計が`0`になるのは偶然ではなく、「信号（周波数1）に含まれる成分の周波数（`+1`と`-1`）が、物差しの周波数`3`とずれているため、直交性によって必ず打ち消し合う」という、DFTの仕組みそのものに由来する結果。これが[6-1本編](6-1-dft.md)で「`k=1`（と`k=7`）以外は正確に`0`になる」と述べていたことの、数式レベルでの根拠になっている。
