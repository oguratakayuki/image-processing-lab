# 1-3 補足資料：`ravel()`による配列の平坦化

[← 1-3. ヒストグラム計算・表示へ戻る](1-3-histogram.md)

`compute_histogram()`内の`channel.ravel()`が何をしているかの補足説明。

## 何をしているか

`channel`は画像なので`(H, W)`の2次元配列。例えば2×3の小さな画像を考える。

```python
channel = [[10, 20, 10],
           [30, 10, 20]]  # shape = (2, 3)
```

`channel.ravel()`はこれを、行ごとに左から右、上から下の順番で並べ直した1次元配列にする。

```python
channel.ravel()  # => [10, 20, 10, 30, 10, 20]   shape = (6,)
```

「平坦化（flatten）」とは、2次元の格子構造をやめて、全ピクセル値を1列に並べ直すこと。

## なぜ必要か

`np.bincount`（ヒストグラムの集計に使っている関数）は**1次元配列しか受け付けない**。「この配列の中に、値0は何個、値1は何個…」と数える関数なので、入力が2次元のままだと使えない。

ここで重要なのは、**ヒストグラムの計算には「どのピクセルがどこにあるか」という位置情報が一切不要**だということ。知りたいのは「値10が何回出現したか」だけで、「それが2行目の3列目にあった」という情報は要らない。だから、2次元を1次元に潰しても何も情報を失わない＝安全に平坦化できる、という理屈になる。

（これは畳み込みとは対照的。畳み込みは「近傍のピクセルとの位置関係」が本質的に重要なので、勝手に1次元化すると近傍の意味が壊れてしまい、できない。）

## 余談：`ravel()` と `flatten()`の違い

NumPyには似た関数`flatten()`もあるが、違いがある。

- `ravel()`：可能な限り**コピーを作らず**、元の配列のメモリをそのまま1次元の「view」として見せる（高速・省メモリ）
- `flatten()`：常に**新しいコピー**を作る（安全だが余分なメモリを使う）

今回は`channel`を書き換える予定がなく、読み取るだけなので、コピー不要な`ravel()`を使うのが合理的。
