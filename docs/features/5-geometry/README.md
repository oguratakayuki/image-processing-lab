# 5. 幾何学的変換（`/lab/geometry`）

[← 機能一覧トップへ戻る](../../../FEATURES.md)

[1-2の明るさ・コントラスト調整](../1-color/1-2-brightness-contrast.md)で学んだ「線形写像→アフィン変換」という数学の流れを、**画素値（1次元）ではなく座標`(x, y)`（2次元）**に適用し直すグループ。これまでの4グループは「値をどう変えるか」を扱ってきたが、ここでは「ピクセルをどこに動かすか」を扱う。

## このグループの流れ

| 番号 | 処理 | 一言で言うと |
|---|---|---|
| [5-1](5-1-translation.md) | 平行移動（Translation） | 座標をベクトル`(tx, ty)`だけずらす。回転・拡大縮小で必須になる「逆方向マッピング」をここで導入する |
| [5-2](5-2-scaling.md) | 拡大縮小（Scaling） | 座標を`(sx, sy)`倍する（対角行列）。逆算した座標が非整数になる問題と、その対処である「最近傍補間」をここで導入する |
| [5-3](5-3-rotation.md) | 回転（Rotation） | 座標を回転行列で回す。直交行列ならではの逆行列の求め方と、回転中心の扱いをここで導入する |
| [5-4](5-4-shear.md) | せん断（Shear） | 長方形を平行四辺形に歪ませる。一般の2×2行列の逆行列（行列式）をここで導入する |

今後、これまでの4つの変換と平行移動を同次座標で統一するアフィン変換、最近傍補間より滑らかなバイリニア補間へと進む予定。

## 数学的な見どころ

- **順方向マッピング vs 逆方向マッピング**：「入力から出力へ書き込む」と出力側に穴が空きうるため、「出力から入力を逆算する」方式を使う。これは平行移動では差が出ないが、拡大縮小・回転・せん断で本質的に重要になる（[詳しくは補足資料](5-1-translation-inverse-mapping.md)）
- **座標変換と画素値変換の違い**：[1〜4のグループ](../../../FEATURES.md)は全て「ある座標の画素値をどう計算するか」だったが、ここでは「どの座標の値を持ってくるか」という、処理の向きが異なる問題を扱う
- **色を一切見ない変換**：[4のモルフォロジー演算](../4-morphology/README.md)はGrayscale変換・閾値処理を前提としていたが、幾何学的変換は座標だけを動かすため、RGB画像にそのまま適用できる（色の計算が一切絡まない）
- **線形変換行列と補間**：[5-2](5-2-scaling.md)の拡大縮小は2×2の対角行列で表せる線形写像。非整数座標が初めて登場し、「最近傍補間」という画素値の決め方が必要になる
- **直交行列の逆行列**：[5-3](5-3-rotation.md)の回転行列は、対角行列とは違う形の逆行列の求め方（転置＝逆回転）を持つ。最近傍補間の限界（孤立した1点が消えることがある）も実例で確認できる
- **一般の2×2行列の逆行列**：[5-4](5-4-shear.md)のせん断行列は対角行列・直交行列どちらの特別な性質も持たず、行列式を使う一般的な逆行列の公式が初めて必要になる

## 実装

- API: `api/app/routers/geometry.py`
- Web: `web/src/app/lab/geometry/page.tsx`（tx/ty・sx/sy・degrees・shx/shyをスライダーで指定し、平行移動・拡大縮小・回転・せん断を適用）
