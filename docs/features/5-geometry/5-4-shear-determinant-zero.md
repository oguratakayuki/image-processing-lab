# 行列式が0だと逆行列が存在しない理由（補足資料）

[← 5-4. せん断へ戻る](5-4-shear.md)

## 超ざっくり言うと

行列式が0の変換は、2次元の図形を1次元の線や1点に押しつぶしてしまう。押しつぶされた後は「元がどこだったか」の情報が失われているので、逆方向に戻しようがない。

## 概念

`M = [[a,b],[c,d]]`という2×2行列による変換は、`det = a・d - b・c`が0でない限り、**異なる入力点は必ず異なる出力点に写る**（1対1対応）。`det = 0`になると、この1対1対応が崩れ、**複数の異なる入力点が同じ1つの出力点に写ってしまう**。逆変換は「出力点から入力点を一意に決める」操作なので、1つの出力点に対して入力候補が複数（あるいは無数に）あると、どれが正解か決めようがなく、逆行列は存在しない。

## 具体例1：`shx=1, shy=1`のせん断（`[5-4](5-4-shear.md)`の行列式）

[5-4のせん断行列](5-4-shear.md)で`det = 1 - shx・shy`だった。`shx=1, shy=1`を代入すると`det = 1 - 1・1 = 0`になる。実際に`shear()`にこの値を渡すと：

```python
>>> shear(image, shx=1.0, shy=1.0)
ZeroDivisionError: division by zero
```

`src_x = (out_x - shx・out_y) / det`の`det`が0になるため、計算そのものが破綻する。これは実装のバグではなく、「この`shx, shy`の組み合わせは数学的に逆変換不可能」という性質がそのままエラーとして現れたもの。

## 具体例2：`[[0, 0], [0, 1]]`（x軸方向を1本の線に潰す）

拡大縮小で`sx=0`にした場合に相当する行列。`det = 0・1 - 0・0 = 0`。

```
入力(3, 5)  -> 出力(0, 5)
入力(-7, 5) -> 出力(0, 5)
入力(0, 5)  -> 出力(0, 5)
```

`x`がどんな値でも、`x'=0`に潰れてしまう。出力`(0, 5)`を見ても、元の`x`が`3`だったのか`-7`だったのか`0`だったのか、情報が失われていて区別がつかない。これが「逆変換できない」の具体的な意味。

## 具体例3：`[[1, 2], [2, 4]]`（平面を1本の斜めの線に潰す）

一見`sx=0`のような分かりやすい形をしていない行列でも、`det = 1・4 - 2・2 = 0`になることがある（2行目が1行目のちょうど2倍になっている＝線形従属）。

```
入力(5, 0)   -> 出力(5, 10)
入力(1, 2)   -> 出力(5, 10)
入力(-3, 4)  -> 出力(5, 10)
```

全く異なる3つの入力点が、すべて同じ出力点`(5, 10)`に写っている。実際、この行列はどんな入力を与えても出力が必ず`y'=2x'`という1本の直線上に乗ってしまう（2次元平面全体が1本の線に押しつぶされる）。

## まとめ

| 行列 | `det` | 何が起きるか |
|---|---|---|
| `[[1,0],[0,1]]`（恒等） | 1 | 潰れない。1対1対応を保つ |
| `[[0,0],[0,1]]` | 0 | x軸方向が1点に潰れる（線へ） |
| `[[1,2],[2,4]]` | 0 | 平面全体が1本の直線に潰れる |
| `[[1,1],[1,1]]`（`shx=shy=1`のせん断） | 0 | 平面全体が1本の直線に潰れる |

`det`は幾何学的には「この変換によって面積が何倍になるか」を表す（符号付きの面積拡大率）。`det=0`は「面積が0倍になる＝図形が潰れる」ことと直接対応している。
