# Q&A一覧

学習を進める中で疑問に思い、質問した内容と回答をまとめたリスト。回答はここに簡潔に記載し、詳しい説明・計算過程は各詳細ページにリンクしている。このリストは今後も随時追加していく。

| # | 質問 | 回答 | 詳細 |
|---|---|---|---|
| 1 | `1-2`で「beta≠0なら原点が動く」とあるが、画像上の位置（ピクセル座標）が動くという意味か？ | いいえ。「原点が動く」とは、変換後の出力値が0になる入力値（`-beta/alpha`）がalpha・betaに応じて変わる、という関数のグラフ上の話。画像上のピクセルの位置が移動するわけではない。 | [1-2. 明るさ・コントラスト調整](../features/1-color/1-2-brightness-contrast.md) |
| 2 | 「重みの和が1という制約のおかげでクリップ不要」とあるが、クリップとは何か？ | 計算結果が表現できる範囲（0〜255）からはみ出した値を、強制的に上限・下限に丸める処理（飽和処理）。重みの和がちょうど1の変換（凸結合）は出力が入力の範囲内に収まることが保証されるため、この丸めが不要になる。 | [1-2. 明るさ・コントラスト調整](../features/1-color/1-2-brightness-contrast.md) |
| 3 | `transformed = alpha * image_float + beta`は線形代数の行列とベクトルの演算か？ | 厳密には違う。これは画像の各要素に同じスカラー`alpha`を掛けて同じスカラー`beta`を足す「スカラーのアフィン変換」であり、要素ごとに異なる重みを混ぜ合わせる行列×ベクトル積（`1-1`のGrayscale変換がこちらに該当）とは別物。 | [1-2. 明るさ・コントラスト調整](../features/1-color/1-2-brightness-contrast.md) |
| 4 | `1-3`の「2次元配列を1次元配列に平坦化（`.ravel()`）」とは何をしているのか？ | 2次元配列の各行を順番に1本につなげて、1次元配列にする操作。ヒストグラム計算で全ピクセルの値を1つずつ数え上げる際に使う。 | [1-3. .ravel()による平坦化（補足資料）](../features/1-color/1-3-histogram-ravel.md) |
| 5 | `(f * h)(x) = ∫ f(τ) h(x - τ) dτ`の`f()`と`h()`とは何か？ | 畳み込まれる2つの関数。画像処理の文脈では、`f`が入力画像、`h`がカーネル（フィルタ）に対応する。 | [2-1. f/h記法（補足資料）](../features/2-convolution/2-1-convolution-fh-notation.md) |
| 6 | `(f*h)(x)`は「`f`と`h`を畳み込んだ結果できる関数に`x`を代入したもの」という理解で合っているか？ | その理解で合っている。`*`は畳み込み演算子で、`f*h`はまず新しい1つの関数を作り出し、`(f*h)(x)`はその関数に`x`を代入して得られる値。 | [2-1. f/h記法（補足資料）](../features/2-convolution/2-1-convolution-fh-notation.md) |
| 7 | `I(x-i, y-j)`という「引き算」の形が「カーネルを180度回転させる」ことと同値、という話だが、なぜその反転が必要なのか？ | 畳み込みの数学的な定義（連続関数の積分の形）をそのまま離散化すると自然にこの形になる、というのが背景。画像処理では対称なカーネル（平均・ガウシアン等）を使うことが多く、反転しても結果が変わらないため実用上はあまり意識しなくてよい。 | [2-1. 畳み込み](../features/2-convolution/2-1-convolution.md) |
| 8 | 畳み込みに使うカーネルには、対称なカーネルと非対称なカーネルがある、という理解で合っているか？ | その理解で合っている。平滑化・鮮鋭化系のカーネル（`mean`, `gaussian`, `laplacian`, `sharpen`）は対称、微分（勾配）系のカーネル（Sobel, Prewitt）は向きの情報を持つため非対称、という綺麗な対応になっている。 | [2-1. 畳み込み（カーネルの対称性と反転の影響）](../features/2-convolution/2-1-convolution.md#カーネルの対称性と反転の影響具体例) |
| 9 | ラプラシアン（`laplacian_kernel`）はなぜ2階微分を使うのか？ | 1階微分はエッジ位置で値が大きくなる「山型」の応答をし、ピークの特定に一手間かかる。2階微分はエッジを境に符号が反転する性質を持ち、その「ゼロ交差」を探すことでエッジの位置をピクセル単位で鋭く特定できる。 | [2-2. なぜ2階微分を使うのか（ゼロ交差によるエッジの検出）](../features/2-convolution/2-2-kernel-presets.md#なぜ2階微分を使うのかゼロ交差によるエッジの検出) |
| 10 | `0 0 0 100 100`の例ではなく、例えば`0 0 100 1000`のように複数のエッジが近くにあった場合も、それぞれ独立に検出できるのか？ | エッジ同士の間隔がカーネルの半径（3×3なら1マス）以上離れていれば、それぞれ独立したゼロ交差として正しく検出できる。間隔がそれより狭いと、2つのエッジの影響が同じマスで重なり合い、綺麗なゼロ交差にならないことがある（実測で確認済み）。 | [2-2. 複数のエッジが近くにある場合](../features/2-convolution/2-2-kernel-presets.md#複数のエッジが近くにある場合) |
| 11 | `3-1`（Sobel）と`3-2`（Prewitt）の使い分けはどんなところか？ | 実務上はSobelが事実上の標準（OpenCV等のデフォルト）。Prewittは「平滑化の重みを変えるとどうなるか」を確認するための比較対象という教材的な位置づけが強く、ノイズ耐性の差は実測した限り決定的ではなかった。 | [3-2. 3-1（Sobel）との使い分け](../features/3-edge/3-2-prewitt.md) |
| 12 | Sobel・Prewittは1階微分、Laplacianは2階微分で、それぞれ同じ用途で使い、Laplacianが一番精度が高い、ということで合っているか？ | 一部正しいが不正確。ノイズの無い理想的な条件での位置特定精度はLaplacianの方が鋭いが、ノイズへの頑健性はSobel/Prewittの方が大きく上回る（実測でLaplacianの相対的なばらつきはSobel/Prewittの約5倍）。「精度が高い」は位置特定精度という1つの軸だけの話であり、総合的な優劣ではない。 | [3-3. Sobel/Prewittとの比較（精度とノイズ耐性）](../features/3-edge/3-3-laplacian.md) |
| 13 | 二値画像（前景255・背景0）の前景とは何か？背景とは何か？ | 画像に内在する性質ではなく、閾値処理（しきい値`T`以上/未満）によるラベル。`T`以上の輝度を持つピクセルが前景（255）、`T`未満が背景（0）というだけで、「どちらが注目したい物体か」という意味論的な区別ではない。暗い物体が明るい背景にある場合は、物体の方が背景(0)側に分類される点に注意。 | [1-4. 閾値処理](../features/1-color/1-4-threshold.md) |
